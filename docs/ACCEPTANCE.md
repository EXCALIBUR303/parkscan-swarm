# Acceptance Criteria

The MVP is **not** complete until every box is ticked *and* the evidence command runs green.

## Functional

| # | Criterion | Evidence |
|---|---|---|
| A1 | One robot navigates to ≥3 inspection waypoints | `make demo` + `pytest -k waypoint_sequence` |
| A2 | One robot autonomously parks at a charging bay | `pytest -k autonomous_docking` |
| A3 | Telemetry reaches the backend and appears in the dashboard | Playwright E2E asserts a marker moves |
| A4 | A detection creates an incident with location, severity, timestamp, evidence | `pytest -k detection_persisted` |
| A5 | Parking spaces represented and displayed available/occupied | `GET /parking-spaces` + component test |
| A6 | 3 robots receive **different** zones, no intentional duplication | `duplicate_visit_rate == 0.0` in the nominal run |
| A7 | ≥1 offline **and** ≥1 low-battery reassignment scenario works | `pytest -k failure_injection` (≥20 injected events) |
| A8 | API endpoints have automated tests | coverage report over `apps/api` |
| A9 | Dashboard has a usable local startup path | `make dev` from a clean clone on this machine |
| A10 | README has exact setup, architecture, limitations, demo checklist | manual review at Phase 6 |
| A11 | **Every claimed metric is regenerated by `make bench`** from a committed `results.csv` | `make bench && git diff --exit-code results.csv` |

## Correctness (these are build failures, not charts)

| # | Criterion |
|---|---|
| C1 | `conflict_count == 0` — no two robots overlapping. Lane-segment driving is met by sensor-based avoidance (leases are not integrated at that granularity); bay-approach collisions, where avoidance is deliberately off, are now arbitrated by `Coordinator._manage_bay_lease` calling the lease layer directly, not merely proven in `test_leases.py` in isolation (ADR-0007) |
| C2 | `depletion_events == 0` — no robot reaches 0% before a bay |
| C3 | `reassignment_churn == 0.0` in the nominal run — proves hysteresis works |
| C4 | `coverage_pct == 100.0` in the nominal run |
| C5 | A stalled robot returning with a **stale fencing token** is rejected by the resource controller — asserted in `test_leases.py` against the controller directly. ⚠️ Still unit-level only: bay *arbitration* is integrated (ADR-0007), but no `ResourceController` sits in the physical docking path, so a resurrected stale holder is not fenced off in a running fleet |
| C6 | A progress report with a stale **epoch** is dropped |
| C7 | The state-machine transition table test covers **all** (state, event) pairs, legal and illegal |
| C8 | Zones tile the lot with zero gaps and zero overlap |
| C9 | `greedy_total >= hungarian_total` over 1000 random cost matrices (property test) |
| C10 | ENU round-trip (lot-metres → WGS84 → lot-metres) within 1 mm |
| C11 | Geolocation rejects (never clamps) rays at or above the horizon |
| C12 | `assert_detector_contract` passes for **every** `Detector` implementation |

## Honesty (non-negotiable)

| # | Rule |
|---|---|
| H1 | `data_source` / `det_source` are NOT NULL columns; the SIMULATED badge is rendered **from the data**, never hardcoded |
| H2 | The badge is persistent and non-dismissable, and appears in `<title>` and the initial live-region announcement |
| H3 | No claim of real-world detection accuracy, ever. Simulated-detector metrics measure the **pipeline** |
| H4 | Model accuracy (mAP@50, mAP@50-95, P/R) is reported **only** for a real model, with the test split named, in a separate `EVAL.md`. Never blended with pipeline metrics into one headline number |
| H5 | No "X% faster" without "in simulation, over 30 seeded runs, versus our own greedy baseline" in the same sentence |
| H6 | Report `reassignment_latency` and `detection_latency` separately — never summed into one recovery figure |
| H7 | If a difference is not statistically significant, say so. "median 4.1% (95% CI −0.8% to 9.3%, 19/30 wins), not significant at this fleet size" beats an unqualified number |
| H8 | Don't say "implemented boustrophedon cellular decomposition" — on an obstacle-free rectangle it degenerates to a lawnmower path. Say "zone decomposition from lot geometry with a back-and-forth sweep per zone" |
| H9 | Don't claim decentralised/consensus allocation while running a central coordinator |
| H10 | Don't claim "optimal coverage" — zones are hand-authored. Say "complete coverage of the modelled lot" |
| H11 | **"Swarm"**: 3 centrally-coordinated robots are a *coordinated fleet*, not a swarm. The project name is kept, but the README's first paragraph defines the term honestly rather than trading on it |
| H12 | Until `ros2-gz` actually runs, never describe this as a ROS 2 system, and never present a `sim-lite` screenshot as a physics simulation |
